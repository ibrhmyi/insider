# PMITC codebook

Every column of every table. Generated by `build/package.py`, which fails if a column lacks a description.

## `data/claims.csv`

| Column | Meaning |
|---|---|
| `claim_id` | row id, CLnnnn; stable across runs (new rows appended) |
| `case_id` | case this claim belongs to (cases.csv) |
| `platform` | polymarket, kalshi, or both |
| `family` | informed_trading, manipulation, oracle/resolution, wash, data leak, control, rule screen (PROTOCOL 2) |
| `subject_type` | address, handle, account, cluster, market or aggregate |
| `subject` | what the claim points at, copied from the source; prefixes kept as prefixes |
| `claim_text` | our paraphrase, under 30 words |
| `evidence_grade` | E1 to E6 (PROTOCOL 5) |
| `amount_claimed_usd` | amount the source states (USD), blank if none |
| `n_accounts_claimed` | number of accounts the source names |
| `event_date` | date of the underlying event (partial dates allowed, A6.3) |
| `claim_date` | date of the claim (partial dates allowed) |
| `source_class` | S1 official, S2 research, S3 press, S4 X analysts, S5 code/data |
| `source_name` | outlet or author; 'X via Y' when the post reached us through Y |
| `url` | source URL (for S4 via search engine: the quoting page until the post URL is recovered) |
| `accessed_date` | date the source was accessed |
| `extractor` | who extracted the row |
| `notes` | free notes (via=search_engine etc.) |
| `run` | collection run that added the row (A6.2) |
| `verified` | true / pending / false (A6.1) |
| `stance` | alleges, disputes, clears or context (A9.1); clearing party in notes |
